# lowki-aa

Account-abstraction primitives for Lowki's paymaster-sponsored Privacy Pools unshields:
ERC-4337 EntryPoint v0.8 userOps, EIP-7702 authorizations, and Kohaku's Privacy Pools
paymaster encodings, ported byte-for-byte. Pure functions only: no RPC, no randomness.
It builds for `wasm32-unknown-unknown` and does not depend on `getrandom`.

`Error`'s `Display` reproduces Kohaku's error strings exactly, for example
`Bundler preVerificationGas 123 exceeds the gas ceiling 100` and
`Bundler gas price exceeds the host RPC bounds (maxFeePerGas=…, maxPriorityFeePerGas=…)`.

### Sponsored-withdrawal flow, as in Kohaku's `paymasterWithdrawThunk`

1. `fee::reasonable_gas_units(is_erc20)` with `call_gas_limit = 0`, or
   `reasonable_gas_units_for_batch(...)` when there is an execution phase. Check the result
   with `assert_gas_limits_within_bounds(&g, &g, 0, &caps)`.
2. Compute `fee = compute_minimum_viable_fee(&gas, max_fee_per_gas)`. For ERC-20, convert it
   with the paymaster's `quoteWeiInToken`, which is on-chain and out of scope here.
3. Build `Withdrawal { processooor: adapter, data: encode_fee_data(&FeeData { recipient, fee_recipient: paymaster, fee, refund_recipient }) }`.
   The proof's `context` must be computed from this withdrawal (see `lowki-pp-core`).
4. Build `paymaster_data = encode_paymaster_data(adapter, &encode_privacy_pool_adapter_data(&withdrawal, &proof))`.
5. Call `build_signed_user_op(&ephemeral, &params)`, then `to_serialized()`, then
   `eth_sendUserOperation(op, ENTRY_POINT_V08)`.

### Signature scheme

The sender is the ephemeral EOA itself. It is 7702-delegated to the canonical v0.8
`Simple7702Account`. It has no factory, so `initCode` is empty and the hash has no 7702
overlay, exactly as in Kohaku. `signature` is the 65-byte `r||s||v` (`v = 27 + yParity`)
over the EIP-712 v0.8 `userOpHash`. That is viem's `signTypedData(getUserOperationTypedData(...))`,
which `Simple7702Account` verifies as `ECDSA.recover(userOpHash, sig) == address(this)`.
The 7702 authorization `{chainId, address: Simple7702, nonce: authorizationNonce ?? nonce}`
is signed with the same key and sent as the `eip7702Auth` field. Like Kohaku, the auth
nonce is rejected above 2^53-1 (Kohaku passes it through JS `Number`).

## Verification

`tests/vectors.rs` loads `vectors/lowki-aa/vectors.json` and asserts byte-for-byte equality.
The vectors were generated by calling the real functions:

- Kohaku `packages/privacy-pools/src` at commit `8c83d64050040654082d70901a46a339bfa103b0`
  (`@kohaku-eth/privacy-pools@0.1.0-alpha.37`), imported from the pinned clone's source:
  `encodeFeeData`, `encodePrivacyPoolAdapterData`, `encodePaymasterData`, `encodePoolWithdraw`,
  `toWithdrawProof`, `buildSignedUserOp`, `prepareNativeShield`, `prepareErc20Shield`,
  `computeMinimumViableFee`, `reasonableGasUnits`, `reasonableGasUnitsForBatch`,
  `assertGasLimitsWithinBounds`, `assertGasPriceWithinBounds`, and `config.ts`.
- viem `2.54.1` (the version Kohaku's lockfile resolves) and ox `0.12.4`:
  `getUserOperationHash({entryPointVersion: "0.8"})`, which is checked to equal
  `hashTypedData(getUserOperationTypedData)`, plus `toPackedUserOperation`,
  `hashAuthorization`, `signAuthorization`, and `erc20Abi` `approve`.
- `@privacy-paymasters/sdk@0.0.5`: its `encodePaymasterData` is checked to equal Kohaku's.

| Area | Cases |
|---|---|
| v0.8 userOp hash and packing (paymaster on/off, factory, 7702 marker with delegate, random EntryPoints, 8 chain ids) | 64 |
| EIP-7702 hash and signature (8 fixed keys, chain id 0 included, nonces up to 2^48) | 48 |
| Paymaster encodings (FeeData, AdapterData, PaymasterData, pool.withdraw, snarkjs → struct) | 48 |
| `buildSignedUserOp`, full signed userOp JSON (no tail calls / 0 / 1 / many calls; ETH and ERC-20 gas; explicit and defaulted nonces; 8 chain ids). Each signature also recovers to the sender in TS | 48 |
| Shield (ETH deposit, ERC-20 deposit and approve) | 40 |
| Fee: `reasonableGasUnits` 2, `…ForBatch` 40, `computeMinimumViableFee` 64, gas-limit bounds 80 (pass and fail, message-exact), gas-price bounds 80 | 266 |

The generator is deterministic: it uses a splitmix64 seed and fixed keys, and re-running it
reproduces the same file.

### Regenerating vectors

```sh
cd vectors/lowki-aa
npm install
npm run gen   # node --import ./resolve-hook.mjs --import tsx gen.ts
```

`resolve-hook.mjs` lets the clone's sources resolve `viem`/`ox` from this directory's
`node_modules` (the clone has none). It also maps `@kohaku-eth/provider` to
`vendor/kohaku/packages/provider/src`.

### Build and test

```sh
export CARGO_TARGET_DIR=/Users/betterclever/projects/ethglobal/lowki/target/lowki-aa
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --target wasm32-unknown-unknown
```

## Known gaps

- **Sepolia has no paymaster.** At the pinned commit, Kohaku's Sepolia config is a
  placeholder (`paymaster = 0x0`, no adapters). The PrivacyPaymaster and the
  PrivacyPoolsFeeAdapter must be deployed before sponsored unshields work on Sepolia.
- The ERC-20 fee needs the paymaster's on-chain `quoteWeiInToken`. Only the wei math is
  here.
- Kohaku's Privacy Pools plugin does not emit the ERC-20 `approve`. `shield_transactions`
  adds the standard `approve(entrypoint, amount)`, verified against viem's `erc20Abi`
  rather than against Kohaku.
- For a `0x7702` factory marker, `init_code_for_hash` follows viem's
  `getInitCode({forHash: true})`. Kohaku itself never sets a factory.
- Gas limits and fee fields are `u128`, because they are packed as uint128 on-chain.
  `pre_verification_gas` and `nonce` are `U256` on `UserOperation`.
- No bundler and no RPC client (`eth_estimateUserOperationGas`, `pimlico_getUserOperationGasPrice`
  and the latest-block base fee belong to the host).
- `alloy-eips` is not used. The 7702 RLP/hash is about 10 lines on `alloy-rlp` and is
  vector-verified.
